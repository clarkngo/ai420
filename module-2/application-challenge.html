Application Challenge 2: Lakeview Property Management Maintenance Tools

Take custom tools and MCP from HOS 2 to a business you haven't seen: rebuild a property manager's badly written tools as a typed MCP server, decide what the agent may remember about tenants, and predict how a model would have misused the originals.

Est. 60–90 minCO1 · CO2Module 2 · end of Week 4IndividualAI assistant allowed — disclose it5% of final grade
Ground rules Scenario Spec Predict misuse Steps Grading Common snags
📏

Ground rules

Everything here runs on your own computer (or in a Codespace) on free tiers, with no credit card. The provided tests use a scripted stand-in model, so they need no API key; the live run uses your free Gemini key.
🏢

The scenario

Lakeview Property Management (fictional) runs 140 rental units in Tacoma. Tenants report problems through a chat agent that looks up their unit, opens a work order, and checks a vendor's web page for availability. The agent works, mostly. Its three tools (legacy_tools.py) were written in a hurry, and the maintenance lead wants them rebuilt properly before more tenants use it.

Two things about the app you should know before you start:

  • The app knows which tenant is logged in. It passes the tenant's ID into every tool call itself. Your schemas must not let the model choose a tenant.
  • Vendor pages are saved copies in vendors/, served by a local test server, so the tests never touch the real web.

📐

The spec

Every requirement below is checked by a provided test in tests/test_server.py.

ToolMust doMust refuse (as an error the model can read)
get_unit(unit_id: str)Return the unit's address, appliances and open work orders, for the logged-in tenant's own unit only.A unit ID not in the form B-101; someone else's unit.
open_work_order(category, description, urgency)Open a work order for the tenant's unit and return its number. category and urgency are enums in the schema.An empty description; a category or urgency not in the enum; a duplicate of an open order in the same category.
read_vendor_page(vendor: str)Return a vendor's page as readable text, at most 4,000 characters, with truncated: true when it cut the text.A vendor not on the approved list. The tool takes a vendor name, never a URL.
The serverServe all three with MCPServer (MCP 2.x), each with a docstring that says when to use it.Anything that writes to stdout, which breaks MCP's stdio connection.

Every error returns {"status": "error", "error": "..."} and changes nothing. That's the HOS 2 rule: errors are data the model can read.

The open decision: what the agent may remember

The maintenance lead wants the agent to "remember tenants so they don't have to repeat themselves." Tenants mention all sorts of things in chat: a dog, a work schedule, a disability, a door code, a dispute with a neighbour. Which details may go into long-term memory, and which must never be stored?

There's no single right answer, and no provided test for this case. You decide, implement your rule in memory.py's should_remember(), prove it with your own tests, and defend it in DECISIONS.md.

🗂️

Predict how the originals would be misused

Before you rewrite them, read the three original tools in legacy_tools.py:

def lookup(q: str, n=10):
    """Look up stuff in the system."""

def do_ticket(stuff: dict):
    """Make a ticket."""

def web(url):
    """Get a web page."""

For each one, predict in your memo one specific way a model would misuse it, and which part of your new schema prevents that. "The model would pass a URL to an internal admin page" is a prediction; "it's insecure" is not.

🪜

Steps & what to submit

1Open it and run the tests

Open your own AC 2 repo (accept the AC 2 invite): clone it and open it in Antigravity (or a Codespace), make the .venv and pip install -r requirements.txt. Then run:

pytest

Almost everything fails with NotImplementedError. That's your to-do list.

2Build the MCP server

Fill in mcp_server/server.py until pytest passes. You may use Antigravity. If you do, ask for a plan first, tell it not to change the tests, and tell it to use the MCP 2.x import (from mcp.server.mcpserver import MCPServer). Read what it writes: you'll defend it.

3Make the memory call

Implement should_remember(fact) with your rule. Write at least two tests in tests/test_my_rules.py: one detail you keep and one you refuse, and add the edge you think is most likely to go wrong.

4Run the agent

Put your free Gemini key in .env, run adk web --session_service_uri "sqlite:///./sessions.db", pick maintenance_agent, and hold two conversations:

Session 1 (tenant T-2207): "The dishwasher in B-114 is leaking. I work nights,
  so please don't send anyone before noon. My door code is 4471."
Session 2 (tenant T-2207, after a restart): "Any update on my dishwasher?"

Copy both sessions, with the tool calls from the Events tab, into TRANSCRIPT.md.

5Write the memo

Fill in DECISIONS.md, about one page: your memory rule and why, your predicted misuse of each original tool, and what Antigravity (or another assistant) wrote, got wrong, or missed.

Submit (via Brightspace)
  • mcp_server/server.py, memory.py and tests/test_my_rules.py
  • The output of pytest, pasted as text (all tests passing, including yours)
  • TRANSCRIPT.md
  • DECISIONS.md

How it's graded

Each criterion is graded on one part of your submission, at one of three levels.

CriterionWeightGraded onFullPartialMissing
Application10%TRANSCRIPT.mdYour server runs in the Lakeview scenario: the right tool fires for each request, and session 2 recalls only what your rule kept.It runs, but one request misbehaves and you don't explain why.It restates the Harbor Supply build, or doesn't run.
Analysis20%DECISIONS.md, section 2 (misuse)For each original tool, a specific misuse, and the part of your schema that prevents it.A risk for each, but only in general terms ("security").No predictions.
Evaluation30%DECISIONS.md, section 1 (memory)A clear rule, judged against stated criteria (what it saves the tenant, what a leak would cost), with an alternative you rejected and why.A rule with a reason, but no criteria or no rejected alternative.No rule, or no justification.
Design40%server.py, memory.py, your tests, and the pytest outputAll provided tests pass, and your own tests check your rule, including an edge case.Most provided tests pass, or your own tests cover only the easy case.It doesn't run, or you wrote no tests of your own.

How this differs from HOS 2's Understand & Refine: there you extended code you already understood, by hand, with no AI. Here the business, the code, and the decisions are new, AI help is allowed, and half the grade (Analysis and Evaluation) is for the calls you make, not the typing.

🧯

Common snags

  • No module named 'mcp.server.fastmcp'. That's the MCP 1.x import. Use from mcp.server.mcpserver import MCPServer.
  • The agent says it has no tools. The server crashed on startup. Run python mcp_server/server.py on its own to see the error.
  • test_model_cannot_choose_the_tenant fails. A schema lists tenant_id. Remove it from the schema; the app passes it in.
  • Plain adk web returns 403 Forbidden in a Codespace. There, add --allow_origins "*". On your own computer you don't need it.
  • 502, 404 or "model not found" when you run the agent. The model is set to gemini-3.8-flash. If your assistant changed it, change it back. See the HOS 2 guide's Common snags.
