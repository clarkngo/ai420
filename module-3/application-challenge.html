Application Challenge 3: Northgate Food Bank Volunteer Scheduler

Take traces and self-correction from HOS 3 to an agent you haven't seen: diagnose three of its failures from exported traces alone, then add the guards its spec asks for, decide when it should hand a change to a human, and say what your guards would still miss.

📏

Ground rules

Everything here runs on your own computer in Antigravity (or in GitHub Codespaces) on free tiers, with no credit card. The provided tests use a scripted stand-in model, so they need no API key; the live run uses your free Gemini key. Your HOS 3 trace recorder is optional here: the guards and tests work without it.
🏢

The scenario

Northgate Community Food Bank (fictional) runs three distribution shifts a week with about 60 volunteers. A scheduling agent fills open shifts, swaps volunteers who can't make it, and sends reminders. Last week it misbehaved three times, and the volunteer coordinator exported the traces (traces/t1.json to t3.json) before anyone looked at the code.

Two things you should know before you start:

  • Diagnose first. Write FAILURES.md from the traces alone and commit it before you open scheduler/. Your commit history shows the order.
  • The food bank's clock is fixed: Wednesday, November 4, 2026. Use scheduler.clock.now().

📐

The spec

Every requirement below is checked by a provided test in tests/test_guards.py. The guards go in scheduler/guards.py as ADK callbacks, and scheduler/agent.py already registers them.

GuardMust doMust not do
error_as_observation (on_tool_error_callback)Turn any exception from a tool into {"status": "error", "error": ..., "hint": ...}.Hide the error: the message must name the tool and the exception.
repeat_call_guard (before_tool_callback)Block the same tool with the same arguments after two calls in one run, and tell the model to answer with what it has. 1002 and "1002" count as the same argument.Block a call whose arguments changed.
step_budget (before_model_callback)Stop the run after 10 model calls with an honest "couldn't finish" reply.Let a short cycle (A → B → A → B) run forever.
Tracing (optional)Record each run with your HOS 3 trace recorder (ADK callbacks) when TRACE=1 is set.Change how the agent behaves, or fail when TRACE isn't set.

The open decision: when to hand off to a coordinator

The coordinator's only instruction was: "Don't let the bot make a mess of the schedule." A guard that retries is fine for a lookup. But a swap that half-worked, a shift with fewer than the minimum volunteers, or a request from someone not on the roster might be better handed to a human. When should the agent stop and hand a shift change to the coordinator instead of retrying?

There's no single right answer, and no provided test for this case. You decide, implement it in needs_handoff() (called by the before_tool_callback), prove it with your own tests, and defend it in DECISIONS.md.

🗂️

Diagnose three traces, before the code

Open the three traces in traces/. Each is one run: every model call and tool call, in order, with arguments and results. For each, write in FAILURES.md:

  • the failure type (tool-call error, invented action, logic loop, wrong data, or wrong tool),
  • the first step where it shows, and your evidence from the trace,
  • the smallest change that would prevent it: a tool fix, a description fix, or a guard.

Then, in your memo: which of the three would you fix first in production, and which would your guards still miss?

🪜

Steps & what to submit

1Diagnose first

Open your own AC 3 repo (accept the AC 3 invite): clone it and open it in Antigravity (or a Codespace). Read the three traces, write FAILURES.md, and commit and push it before you open scheduler/.

2Run the tests

Run pytest. The guard tests fail with NotImplementedError. That's your to-do list.

3Build the guards

Fill in scheduler/guards.py until pytest passes. You may use Antigravity. If you do, ask for a plan first, and tell it not to change tools.py or the tests. Read what it writes: you'll defend it.

4Make the hand-off call

Implement needs_handoff() with your rule. Write at least two tests in tests/test_my_rules.py: one that hands off and one that doesn't, and add the edge you think is most likely to go wrong.

5Run the scheduler

Put your free Gemini key in .env, then replay the three requests from the traces with your guards on:

python run_requests.py --guards on

Copy the three runs, tool calls included, into TRANSCRIPT.md, and say for each whether it now recovers, stops safely, or hands off.

6Write the memo

Fill in DECISIONS.md, about one page: your hand-off rule and why, which failure you'd fix first, what your guards would still miss, and what Antigravity (or another assistant) wrote, got wrong, or missed.

Submit (via Brightspace)
  • FAILURES.md, committed before any change to scheduler/
  • scheduler/guards.py and tests/test_my_rules.py
  • The output of pytest, pasted as text (all tests passing, including yours)
  • TRANSCRIPT.md
  • DECISIONS.md

How it's graded

Each criterion is graded on one part of your submission, at one of three levels.

CriterionWeightGraded onFullPartialMissing

Evaluation30%DECISIONS.md (hand-off rule, fix-first, what guards miss)A clear hand-off rule judged against stated criteria (cost of a wrong change, coordinator's time), a fix-first call, and an honest account of what the guards miss.A rule with a reason, but no criteria, or no account of what the guards miss.No rule, or no justification.

How this differs from HOS 3's Understand & Refine: there you extended code you already understood, by hand, with no AI. Here the business, the code, and the decisions are new, AI help is allowed, and half the grade (Analysis and Evaluation) is for the calls you make, not the typing.

🧯

Common snags

  • test_repeat_guard_normalises_args fails. You compared arguments as-is. Compare them after turning every value into a string.
  • test_short_cycle_is_stopped fails. The repeat guard can't catch A → B → A → B; only the step budget can. Check the budget counts model calls, not tool calls.
  • You want to see what a test run did. Copy your HOS 3 tracing.py in and run the live agent with TRACE=1, or open it in adk web and use the Trace view.
  • 502, 404 or "model not found" when you run the agent. The model is set to gemini-3.8-flash. If Antigravity changed it, change it back. See the HOS 3 guide's Common snags.
