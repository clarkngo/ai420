Application Challenge 1: Evergreen Getaways Trip Planner

Take your HOS 1 agent skills to a business you haven't seen: build a travel agency's planning agent in ADK from a written spec, make one decision the spec leaves open, and decide which of the agency's requests need an agent at all.

Est. 60–90 minCO1 · CO2Module 1 · end of Week 2IndividualAI assistant allowed — disclose it5% of final grade
Ground rules Scenario Spec Five requests Steps Grading Common snags
📏

Ground rules

Everything here runs on your own computer (or in a Codespace) on free tiers, with no credit card. The provided tests use a scripted stand-in model, so they need no API key; the live run uses your free Gemini key.
🏢

The scenario

Evergreen Getaways (fictional) is a three-person travel agency in Bellingham. Customers email requests like "three days in Victoria, B.C., under $900, with one rainy-day option." An agent drafts the itinerary for a travel agent to check. A teammate already wrote the tools (planner/tools.py: search_ferries, search_hotels, get_forecast and add_up). The ADK agent that uses them, and the run() function the agency's email system calls, are missing. That's your job.

Two things about the app you should know before you start:

  • The tests use a scripted stand-in model (tests/fake_model.py, an ADK model class) that replies with tool calls in a fixed order, so the tests are the same every run.
  • The agency's clock is fixed: Monday, November 2, 2026. Use planner.tools.today(), never date.today().

📐

The spec

Every requirement below is checked by a provided test in tests/test_agent.py.

PartMust doMust not do
root_agent in planner/agent.pyAn ADK Agent with the four tools, and an instruction that quotes prices and sailings only from tool results and totals with add_up.Give it tools it doesn't need, or let it invent a price.
run(request, max_llm_calls=6, model=None) in planner/run.pyRun root_agent with ADK's InMemoryRunner and RunConfig(max_llm_calls=...). Return a dict with answer, status ("done", "out_of_steps" or "error"), model_calls, tool_calls and log.Raise. Every outcome is a dict, including ADK's budget error.
The logBuild log from the run's events: every tool call with its name, arguments and result, in order.Log what you expected to happen instead of what the events show.
Tool errorsA tool's {"error": ...} reaches the model as a function response, and the run keeps going.Stop the run on the first tool error, or hide the error from the model.
Step budgetWhen ADK stops the run at max_llm_calls, return status="out_of_steps" with your out-of-steps answer.Retry with a bigger budget "to wrap up".

The open decision: running out of steps

The agency owner's only instruction was: "Never send a customer a half-planned trip as if it were finished." When the budget runs out, the run has partial findings in its events: maybe a ferry and a forecast, but no hotel. What does the customer-facing answer say? The partial plan, clearly marked? Nothing but an apology? A hand-off to a travel agent with the findings attached?

There's no single right answer, and no provided test for this case. You decide, implement it in run(), prove it with your own tests, and defend it in DECISIONS.md.

🗂️

The agency's five requests

The owner also wants to "use the agent for everything." You don't build these. In your memo, decide for each: an agent, a single model call, or a plain script, and say why. "A script" with a good reason is a strong answer.

  1. Turn a customer's email into a draft itinerary.
  2. Send every customer a reminder 48 hours before departure.
  3. Rewrite a finished itinerary in a friendlier tone.
  4. Rebook a whole group when a ferry sailing is cancelled.
  5. Total the agency's bookings for the month.
🪜

Steps & what to submit

1Open it and run the tests

Accept the AC 1 invite, clone your repo and open it in Antigravity (or a Codespace). Make the .venv, pip install -r requirements.txt, then run:

pytest

Almost everything fails with NotImplementedError. That's your to-do list.

2Build the agent and run()

Fill in planner/agent.py and planner/run.py until pytest passes. You may use Antigravity. If you do, ask for a plan first (/plan), tell it to keep MODEL = "gemini-3.8-flash" and not to change the tests, and read what it writes: you'll defend it.

3Make the out-of-steps call

Implement your rule for running out of steps. Write at least two tests in tests/test_my_rules.py: one showing your rule, and one for the edge you think is most likely to go wrong. The fake model has a script that never finishes; the file shows how to use it.

4Run the planner

Put your free Gemini key in .env (copied from .env.example), then run one request with the full budget and one with a budget of 2. The planner prints every tool call from the events, so the transcript shows what actually ran. You can also watch a run in adk web.

python -m planner "3 days in Victoria, B.C., under $900, with one rainy-day option"
python -m planner --max-llm-calls 2 "3 days in Victoria, B.C., under $900"

Copy both runs, tool lines included, into TRANSCRIPT.md. If the planner does something you didn't expect, keep it in and say so in your memo.

5Write the memo

Fill in DECISIONS.md, about one page: your out-of-steps rule and why, your call on each of the five requests, and what Antigravity (or another assistant) wrote, got wrong, or missed.

Submit (via Brightspace)
  • planner/agent.py, planner/run.py and tests/test_my_rules.py
  • The output of pytest, pasted as text (all tests passing, including yours)
  • TRANSCRIPT.md
  • DECISIONS.md

How it's graded

Each criterion is graded on one part of your submission, at one of three levels.

Evaluation30%DECISIONS.md, section 1 (out of steps)A clear rule, judged against stated criteria (what the customer could do with it, what it risks), with an alternative you rejected and why.A rule with a reason, but no criteria or no rejected alternative.No rule, or no justification.

How this differs from HOS 1's Understand & Refine: there you extended code you already understood, by hand, with no AI. Here the business, the code, and the decisions are new, AI help is allowed, and half the grade (Analysis and Evaluation) is for the calls you make, not the typing.

🧯

Common snags

  • test_budget_returns_dict fails with an exception. ADK raises an error when max_llm_calls is spent. Catch that one error in run() and return status="out_of_steps"; let other errors become status="error".
  • The live run never calls a tool. Check the tool docstrings and the instruction: the model only calls a tool when it can tell what the tool is for.
  • The log is empty. Collect events from the runner as they arrive; function calls and responses are in each event's content parts.
  • A date test fails by one day. Somewhere you used date.today(). Use planner.tools.today().
  • 502, 404 or "model not found" when you run the agent. The model is set to gemini-3.8-flash. If your assistant changed it, change it back. See the HOS 1 guide's Common snags.
